\subsection{Trusted Base}
\label{sec:validation}
% 분량: 1쪽. 번역(4.2)의 검증, 그리고 증명 밖에서 믿어야 하는 구성 요소를 함께 다룬다.

\draft{Every result depends on the translation of Section~\ref{sec:translation}, so we test that the Lean specification of P4 agrees with the reference type checker and interpreter.}
% 실행 관계와 reference interpreter의 일치 검사 방법도 적을 것.

\draft{In one direction, every program from the proven \texttt{program\_ok} generator must be accepted by the reference type checker.}

\draft{In the other direction, which the generator cannot check because it only produces programs Lean accepts, we run an existing P4 corpus through both.}
% 코퍼스에 ill-typed 프로그램도 넣어야 Lean이 거부하는 방향까지 검사된다.

\draft{Besides the translation, the trusted base consists of the serializer and extractor, the script that derives the generator statement, the Lean compiler that runs the generator and the oracle, and the Lean kernel with its three standard axioms.}
% pbt.verify는 아직 모든 공리를 거부한다(rejectAxioms). 세 공리 허용으로 바꾼 뒤 이 문장을 확정할 것.

\subsection{RQ2: Necessity of Verification}
\label{sec:rq2}
% 분량: 0.75쪽

\draft{RQ2 asks what goes wrong when the same agent writes the property and the generator without Lean (Table~\ref{tab:rq2}).}

\draft{Invalid properties and unsound generators cause false alarms, which we count.}
% 확인: Lean 없이 쓴 성질이 invalid인지 판정하는 기준(Lean에서 반증, 반례 확인 등).

\draft{Incomplete generators hide bugs without any visible sign, so we also count the inputs up to a size bound that they can never produce, and the known bugs they consequently miss.}
