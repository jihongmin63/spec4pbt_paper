\section{Introduction}
\label{sec:intro}

Property-based testing (PBT) relies on properties that describe expected behavior and generators that supply test inputs~\cite{claessen00quickcheck}.
Constructing generators that can effectively exercise the target behavior requires substantial effort.
Agents open a new route by automatically constructing generators from user-supplied properties.
As with hand-written generators, however, trusting the resulting tests requires checking that the property is valid and that the generator is correct.
Because mechanized language specifications give the language a precise meaning, they provide a foundation on which property validity and generator correctness can be stated and proved~\cite{youn25west,paraskevopoulou15foundational}.
We therefore present an approach in which agents construct a precondition generator and proofs of a given property and the generator’s correctness, then use the property and generator to test external implementations only after an interactive theorem prover (ITP) verifies both proofs.
We investigate this approach by implementing it for SpecTec specifications in \texttt{spec4pbt} and applying it to P4.

This paper makes three contributions:
\begin{itemize}
  \item An account of three challenges that trustworthy property-based testing of language implementations from mechanized specifications must address: property validity, generator and its effectiveness, and the correspondence between the property and executable checks of implementation behavior (Section~\ref{sec:three-propositions}).
  \item \texttt{spec4pbt}, which handles the challenges for SpecTec specifications with Lean (Section~\ref{sec:instantiation}). 
  \item A case study on P4, including a comparison with Failing with Purpose~\cite{lee26fwp} (Section~\ref{sec:evaluation}).
\end{itemize}
