\section{Introduction}
\label{sec:introduction}

% Motivation: generators of valid inputs are essential but hard to construct.
Constructing efficient generators for inputs satisfying a given predicate is
often difficult in property-based testing (PBT)~\cite{claessen00quickcheck}.
Many properties apply only to inputs that satisfy a precondition.
Inputs that do not satisfy the precondition cannot falsify such a property.
When few randomly generated inputs satisfy the precondition, discarding
invalid inputs wastes much of the testing
effort~\cite{lampropoulos18generators}.
Generating valid inputs directly requires incorporating the predicate's
constraints into generation while maintaining efficiency and input diversity.
In an interview study, experienced users named writing generators as a main
source of complexity in PBT~\cite{goldstein24practice}.

% Existing automation reduces manual effort, but approaches have different limitations.
Existing techniques automate generator
construction~\cite{lampropoulos18generators,paraskevopoulou22computing,prinz23merging,mittelman26testing,goldstein26palamedes},
but, depending on the predicate, an approach may fail to construct a generator
or produce an inefficient one.
Paraskevopoulou et al.~\cite{paraskevopoulou22computing} derive generators by
processing the premises of inductive relations in sequence, but generation can
be inefficient when dependent constraints occur in an unfavorable order.
Prinz and Lampropoulos~\cite{prinz23merging} merge relations to guide generation
with multiple constraints, but merging offers limited benefit when the relations
do not share recursive structure and may require reformulation to expose that
structure.
Mittelman et al.~\cite{mittelman26testing} automatically select generation modes
and premise order.
We note a potential limitation of this approach: its scheduling procedure
generates each variable from at most one precondition, so other constraints on
that variable may still need to be checked after generation.
Goldstein et al.~\cite{goldstein26palamedes} synthesize generators using predefined deductive
rules and transformations of recursive predicates, but synthesis can fail when
the automation cannot convert a predicate into a supported recursive form or
lacks a required predefined generator.
As these limitations show, no single approach is efficient for every predicate.
Constructing an efficient generator therefore requires selecting a suitable approach
for each predicate.
This selection is not obvious because the conditions under which each approach
works best, such as how dependent constraints should be ordered or whether
relations share recursive structure, are often not apparent from the syntax of
the predicate.

% Proposed response: agents can adapt their approach to construct efficient generators.
Agents offer a new way to construct generators because they can reason about the
semantics of a predicate, not only its syntax.
This lets them apply a suitable strategy for generating inputs that satisfy the
predicate and even find an easier problem to solve, such as a logically equivalent
predicate that admits a more efficient generator.
Prior work has explored using agents for PBT of real-world
software~\cite{maaz25agentic}.

% Agent limitations: reliability (illustrated by agentic PBT) and scalability.
However, agentic generator construction faces two challenges:
\emph{reliability} and \emph{scalability}.
Without verification, an agent-constructed generator may be unsound or
incomplete.
An unsound generator produces inputs that violate the predicate, causing false
alarms.
An incomplete generator never produces some valid inputs, possibly missing bugs.
Unverified agent output undermines reliability in practice: in agentic PBT,
where the agent writes both properties and generators, only 56\% of sampled bug
reports were valid~\cite{maaz25agentic}.
As specifications and properties grow more complex, finding efficient generation
strategies and constructing correctness proofs for the resulting generators become
more demanding.
An agent may therefore require many attempts or fail within the available budget.
Moreover, because agent runs are nondeterministic, the number of attempts
construction requires and whether it succeeds are hard to predict.

% ITP proofs can ensure reliability but worsen the scalability challenge.
Of these two challenges, reliability can be addressed by formalizing generators
in an interactive theorem prover and proving them correct.
Lampropoulos et al.~\cite{lampropoulos18generators} and Goldstein
et al.~\cite{goldstein26palamedes} already prove the soundness and completeness
of the generators they derive automatically.
Likewise, attaching such proofs to agent-constructed generators would guarantee
their correctness.
However, the agent must then construct proofs in addition to generators, which
makes generator construction harder to scale.

% Proposal: the agent transforms predicates in an IR; generators and proofs are derived mechanically.
As one way to scale agentic generator construction, this paper proposes an
approach in which an agent transforms the predicate rather than writing the
generator and its proofs.
The agent rewrites the predicate in an intermediate representation (IR) into an
equivalent form that admits efficient generation, proving each step correct.
From this form, the generator and its correctness proofs are derived
mechanically.

% Evaluation: experiments on a SpecTec-based toolchain.
To evaluate the approach, we build a toolchain on top of
SpecTec~\cite{youn24spectec}, a domain-specific language for specifying
programming languages, and run experiments with it.
While SpecTec is used to write the language specification, the toolchain takes
such a specification and a property over it and constructs a verified generator
for the property's precondition with the proposed approach.
It then uses the generator to test external implementations of the language
against the property.
